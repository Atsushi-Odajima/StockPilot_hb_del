# DECISIONS — 設計判断と理由

| ID | 判断 | 理由・代替案 |
|---|---|---|
| D-01 | TypeScript（TS 7.0.2）＋ Fastify 5.12.5 ＋ zod 4.6.5 ＋ node-postgres 8.23.0、React 19.3 ＋ Vite 8.3.1、PostgreSQL 16 | 仕様の第一候補。調査時点（2026-09-29）の npm latest 安定版を `save-exact` で固定。TS 7 で型検査が通ることを確認 |
| D-02 | 単一リポジトリ内の単一パッケージ（server / web / shared / domain） | 共有スキーマ（zod）と数量ロジックを1か所に置き、クライアント計算で在庫を確定しない |
| D-03 | 認証は自前（scrypt＋DBセッション）。「管理型認証」は採用しない | 外部アカウント・契約がなく、テスト可能性を優先。移行時は `services/auth.ts` を差し替える。メール送信は未契約 |
| D-04 | データ世代＝ワークスペース。業務テーブルは (ws_id, id) 複合キー | 事業者分離（DB制約）、サンプル領域、復元の staging→原子的切替、dataEpoch を同じ仕組みで実現。行レベルセキュリティは使わない（単一サーバー経路。T26 で分離を試験） |
| D-05 | 在庫は追記のみの台帳＋同一トランザクションの残高キャッシュ | 仕様 §6。残高は再計算照合可能（verify API） |
| D-06 | 同時実行制御：場所行の FOR UPDATE をID順に取得し、その後に残高行 | 存在しない残高行の競合（初回入庫・初期在庫）を場所ロックで直列化。棚卸停止と入庫の順序も同じロックで決まる（T22）。全経路で順序を統一（inventory.ts 冒頭） |
| D-07 | 採番（伝票・発注・棚卸番号）は workspaces 行カウンタ。ロックは常に最後 | 連番を事業者ごとに保つ。デッドロック防止のため最後に取得 |
| D-08 | 冪等性は command_log（(ws,key) 主キー、要求内容ハッシュ）を同一トランザクションで挿入 | 同キー同時送信は一意索引で待たされ、先行コミット後に前回結果を返す（T02） |
| D-09 | 棚卸停止は業務状態（locations.stocktake_id）で表現し、DBロックを保持しない | 仕様 §13。基準リビジョン（locations.rev）で開始後の変更を検出 |
| D-10 | 取消可能数量は元伝票ヘッダーをロックして集計 | 取消と返品の上限を1つの式（残り＝元−取消済−返品済）で管理 |
| D-11 | PDF は pdfkit 0.20.2 でサーバー生成、フォントは Noto Sans JP（SIL OFL 1.1）をサブセット埋め込み | OSフォントを同梱しない。任意URL・HTMLを読まない。帳票はスナップショットから再生成 |
| D-12 | QR は qrcode 1.5.4、読取は barcode-detector 3.2.2（ponyfill、zxing-wasm 3.1.x）。ネイティブ BarcodeDetector が QR・EAN-13 に対応すれば優先 | 仕様 §14・R2。wasm は自前配信（CDN不使用、CSP で self のみ） |
| D-13 | 対応形式：QR・EAN-13・EAN-8・Code128（デコーダ設定）。自動試験で確認済みは QR と EAN-13 | Code128・EAN-8 は設定済みだがカメラ試験未実施（TEST_REPORT） |
| D-14 | CSV は papaparse 5.7.0、Shift_JIS は TextDecoder（明示選択） | 単純 split を使わない。自動判定はしない |
| D-15 | バックアップは yazl/yauzl の ZIP＋manifest（schemaVersion・件数・sha256） | 一貫スナップショットは REPEATABLE READ の読取専用トランザクション。写真は内容アドレスで不変 |
| D-16 | Service Worker は自作（外枠のみキャッシュ、更新は利用者操作で適用） | vite-plugin-pwa より挙動を限定しやすい |
| D-17 | 写真のHEICは拒否してJPEG選択を案内 | サーバー変換を入れない。iPhone Safari のファイル選択は通常JPEGへ変換して渡すが、実機未確認 |
| D-18 | 保存先はローカル永続ディスク（Storage インターフェース） | S3互換（R2等）ドライバは残作業 |
| D-19 | 補充の「発注残 O」は通常場所へ入る発注済み明細のみ | 保留場所への入荷は利用可能にならないため |
| D-20 | レート制限は環境変数で変更可能（既定：認証10/分、全体600/分/IP） | E2E で同一IPから大量アクセスするため。本番は既定値 |
